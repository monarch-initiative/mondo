# Mondo ↔ ICD-10-CM chapter XVII (Q00–Q99) alignment analysis

Analysis of Mondo's alignment with the ICD-10-CM congenital malformations
chapter. **Nothing in this directory has been applied to the ontology.** Every
table is a proposal for curator review.

Generated by `analyze.py` against `src/ontology/mondo-edit.obo` and
`sqlite:obo:icd10cm`. Re-run with `python3 analyze.py` (needs the TSV dumps
described at the bottom). Point it at a different edit file with
`MONDO_EDIT=... OUT_DIR=... python3 analyze.py`.

**Baseline for all numbers below: commit `82bde5430`,** i.e. before the PR1
changes described under "Applied changes". Reproduce with:

```sh
git show 82bde5430:src/ontology/mondo-edit.obo > /tmp/mondo-head.obo
MONDO_EDIT=/tmp/mondo-head.obo OUT_DIR=/tmp/baseline python3 analyze.py
```

## Headline

ICD-10-CM chapter XVII has **1067 codes**. 494 are referenced somewhere in
`mondo-edit.obo`, but that number badly overstates the alignment:

| Xref qualifier on `xref: ICD10CM:Q*` lines | count |
|---|---:|
| `provenance-only` (`{source="Orphanet:2695"}`, `{source="DOID:10485"}`) — **no mapping predicate at all** | 2459 |
| `MONDO:equivalentTo` | 161 |
| Orphanet `btnt` / `specific` / `e` qualifiers | 231 |
| `mondoIsNarrowerThanSource` | 16 |
| other `MONDO:` qualifiers (`equivalentToOther`, `mondoSubClassOfSource`, `directSiblingOf`) | 5 |
| `relatedTo` / `obsoleteEquivalent` / unqualified | 5 |

So of ~2880 xref assertions, **161 are curated equivalences**. The rest is
inherited Orphanet and DOID provenance that has never been assigned a mapping
predicate. The dominant real relationship is many-Mondo-diseases → one coarse
ICD bucket, which is `skos:broadMatch`, not equivalence.

Qualifiers must be matched **exactly**, not by substring: `equivalentToOther`
and `equivalentToUnspecified` both contain `equivalentTo`, and
`obsoleteEquivalentObsolete` contains `obsoleteEquivalent`. Counting by
substring inflates the curated-equivalence figure and produces phantom
findings.

## Scope policy (workstream 4)

Not every ICD code can or should map to a Mondo disease. Codes are classified
by **label**, not by position in the hierarchy — having ICD children does not
make a code a container. `Q35 Cleft palate` has five children and is still
exactly `MONDO:0016064 cleft palate`.

| Bucket | n | In scope? | Rationale |
|---|---:|---|---|
| `DISEASE` | 439 | **yes** | A nameable condition. Eligible for `exactMatch`. |
| `RESIDUAL` | 357 | no | "unspecified", "other specified". A code for *what is left over*, so it has no stable extension. |
| `LATERALITY` | 107 | no | left/right/bilateral variants of a sibling. Mondo does not model laterality; map the parent instead. |
| `CONTAINER` | 80 | broadMatch only | "Congenital malformations of X", enumerations like "Anophthalmos, microphthalmos and macrophthalmos". |
| `BLOCK` | 12 | broadMatch only | Chapter/block ranges (`Q00-Q07`). |
| `PHENOTYPE` | 72 | **decision needed** | The exact label is in HPO and absent from Mondo — `Q13.5 Blue sclera` = `HP:0000592`, `Q17.1 Macrotia` = `HP:0000400`. |

**222 out-of-scope codes currently carry Mondo xrefs** (129 residual, 38
container, 27 phenotype, 16 laterality, 12 block). These aren't necessarily
wrong as `broadMatch`, but none should be `equivalentTo`.

The `PHENOTYPE` bucket is the one genuine policy question here: does Mondo
want disease classes for things HPO already covers as phenotypic
abnormalities? The 72 codes are listed in `04_exclusion_list.tsv`. Note this
is a **lower bound** — detection requires an exact string match to an HPO
label, so `Q18.3 Webbing of neck` is missed because HPO spells it "Webbed
neck".

## Workstream outputs

### `01_proposed_exactmatch.tsv` — 24 rows
In-scope codes with no existing xref and a confident lexical match.
13 are clean; the rest carry a `review_flag`:

- **`Mondo term may include acquired`** (5) — ICD says "congenital", the Mondo
  term does not (`Q76.2 Congenital spondylolisthesis` → `MONDO:0008475
  spondylolisthesis`). ICD codes acquired spondylolisthesis separately at
  `M43.1`, so these may be narrowMatch.
- **`tier B: lossy match, verify`** (5) — matched only after discarding word
  order and connectives, which collapses `Q37 Cleft palate with cleft lip`
  into `MONDO:0016044 cleft lip/palate` (a grouping covering lip *or* palate
  *or* both — likely narrowMatch).
- **`generic Mondo parent`** (1) — proposed as `broadMatch` instead.

Worth noting `Q51.21 Complete doubling of uterus` → `MONDO:0015840 complete
septate uterus` looks wrong but is correct: ICD-10-CM lists "Complete septate
uterus" as an inclusion term for that code, and Mondo currently xrefs only the
coarser `Q51.2`, so this is a refinement.

### `02_xref_audit.tsv` — 2720 rows

| Verdict | n | Meaning |
|---|---:|---|
| `KEEP-as-broadMatch` | 2412 | Points at a residual/container/block code, or shares the code with other Mondo terms. Correct as broadMatch; should be labelled as such rather than left unqualified. |
| `OK` | 148 | Already curated `equivalentTo` on a disease code. |
| `REVIEW-phenotype` | 83 | Target is an HPO-domain phenotype. |
| `REVIEW` | 66 | 1:1 but labels disagree, or a conjunctive label. |
| `DEMOTE->broadMatch` | 8 | **`equivalentTo` asserted on a code that cannot have an exact equivalent.** |
| `PROMOTE->exactMatch` | 3 | 1:1 with label agreement, currently provenance-only. |

The 8 demotions are the clearest defects — e.g.
`Q00-Q99 Congenital malformations, deformations and chromosomal abnormalities`
is asserted `equivalentTo MONDO:0021147 disorder of development or
morphogenesis`, and `Q13.4 Other congenital corneal malformations` (a residual
code) is asserted `equivalentTo MONDO:0000733 cornea plana`.

### `03_new_term_candidates.tsv` — 142 rows
`DISEASE` codes with no xref and no lexical match. Each carries up to three
trigram nearest neighbours as leads.

**The neighbour score cannot be used to decide anything.** It is string
similarity, and near-misses score high precisely because they are near-misses:
`Q55.23 Scrotal transposition` scores 0.71 against `penoscrotal transposition`
and `Q75.5 Oculomandibular dysostosis` scores 0.72 against `otomandibular
dysostosis` — different conditions in both cases. Conversely `Q04.4
Septo-optic dysplasia of brain` scores only 0.63 against `MONDO:0008428
septooptic dysplasia`, which *is* the right term. Treat the column as a
starting point for lookup, nothing more.

This list also still contains phenotypes the HPO test missed (`Q18.3 Webbing
of neck`, `Q18.6 Macrocheilia`, `Q17.0 Accessory auricle`), so it needs a
phenotype triage pass before any term minting.

### `04_exclusion_list.tsv` — 628 rows
Every out-of-scope code with its bucket, HPO equivalent where detected, and
whether Mondo currently xrefs it.

### `00_q_codes_classified.tsv` — 1067 rows
All Q codes with bucket, depth, child count, existing xrefs and predicates,
and match results. The source table behind the other four.

## Xref label convention

Curators cannot check `xref: ICD10CM:Q87.83 {source="..."}` without looking the
code up. Three styles were tested through the real NORM pipeline
(`owltools --merge-axiom-annotations` then `robot convert`) on the full 44 MB
edit file:

| Style | Survives NORM? |
|---|---|
| `xref: ICD10CM:Q87.83 {source="..."} ! Bardet-Biedl syndrome` | ❌ **silently stripped** |
| `xref: ICD10CM:Q87.86 "Kleefstra syndrome"` | ✅ preserved |
| `xref: ICD10CM:Q93.52 "Phelan-McDermid syndrome" {source="..."}` | ✅ both preserved |

The trailing `!` comment familiar from `is_a` and `relationship` lines does
**not** work on xrefs. The OBO-native quoted description does, and round-trips
to `Annotation(rdfs:label "...")` on the `hasDbXref` axiom in OWL.

This repo had **zero** uses of the quoted form before PR1, so it is a new
convention. It is being adopted for ICD-10-CM Q-chapter work so the diff is
self-checking: the ICD label sits next to the Mondo term name.

## Applied changes

### PR1 — mapping-predicate defects (9 xrefs, done)

Eight `equivalentTo` assertions demoted to `mondoIsNarrowerThanSource` (which
exports as `skos:broadMatch`), because the ICD target is a block, residual or
container code that cannot have an exact equivalent:

| Mondo | ICD | ICD bucket |
|---|---|---|
| MONDO:0020022 central nervous system malformation | Q00-Q07 | BLOCK |
| MONDO:0021147 disorder of development or morphogenesis | Q00-Q99 | BLOCK |
| MONDO:0016044 cleft lip/palate | Q35-Q37 | BLOCK |
| MONDO:0019356 urogenital tract malformation | Q60-Q64 | BLOCK |
| MONDO:0019040 chromosomal disorder | Q90-Q99 | BLOCK |
| MONDO:0000733 cornea plana | Q13.4 | RESIDUAL |
| MONDO:0019817 congenital mitral valve insufficiency and/or stenosis | Q23 | CONTAINER |
| MONDO:0001046 imperforate anus | Q42.3 | CONTAINER |

Plus one malformed qualifier: `MONDO:0031322 triopia` carried
`source="MONDO:mondoIsNarrowerThanSource."` — a **trailing period**, which
makes the qualifier unparseable and silently drops the mapping from the
broadMatch SSSOM export. Corrected.

`Q56.3 Pseudohermaphroditism, unspecified` → `MONDO:0005518` was in an earlier
draft of this list but is **not** a defect: it carries `equivalentToOther`,
not `equivalentTo`, so it never asserted an equivalence.

### PR2 — new exactMatches and promotions (16 xrefs, done)

13 new `MONDO:equivalentTo` xrefs on codes that had none, and 3 promotions of
provenance-only xrefs that were already 1:1 with label agreement
(`Q10.0` congenital ptosis, `Q32.0` congenital tracheomalacia, `Q83.1`
accessory breast — each already carried the Orphanet `/e` exact qualifier).

**Superseded-parent pattern.** 10 of the 13 target terms already xreffed the
*parent* ICD code with pure Orphanet/DOID provenance:

| Mondo term | had | now also has |
|---|---|---|
| Bardet-Biedl syndrome | Q87.8, Q87.89 | **Q87.83** |
| Laurence-Moon syndrome | Q87.8 | **Q87.84** |
| MED13L syndrome | Q87.8 | **Q87.85** |
| Kleefstra syndrome | Q87.8 | **Q87.86** |
| von Hippel-Lindau disease | Q85.8 | **Q85.83** |
| Alagille syndrome | Q44.7 | **Q44.71** |
| Phelan-McDermid syndrome | Q93.5 | **Q93.52** |
| complete / partial septate uterus | Q51.2 | **Q51.21 / Q51.22** |

ICD-10-CM has been carving named syndromes out of residual buckets
(`Q87.8 Other specified congenital malformation syndromes, NEC`) into their
own codes. Mondo's inherited mappings still point at the superseded parent.

The parent xrefs were **left untouched** in PR2. They are unqualified, so they
export as `oboInOwl:hasDbXref` rather than as a semantic mapping, and
therefore do not contradict the new `exactMatch`. Deciding whether they should
become `broadMatch` or be retired belongs with the bulk pass (step 4), not
scattered across per-organ batches. Worth searching the other 2412
`KEEP-as-broadMatch` rows for the same pattern when that pass happens.

## Suggested order of work

1. **Fix the 9 demotions** — small, unambiguous, they are asserted errors.
2. **Decide the phenotype policy** — gates 72 codes and 83 audit rows; nothing
   downstream can be settled without it.
3. **Apply the 13 clean exactMatches**, then work the 11 flagged ones.
4. **Qualify the provenance-only bulk** — 2411 xrefs that should carry
   `broadMatch` rather than nothing. Mechanical once the policy is agreed.
5. **New terms last** — needs the phenotype triage first, and 166 unmapped
   `DISEASE` codes is a large curation effort on its own.

## Regenerating

`analyze.py` reads four TSVs from `/tmp` produced by:

```sh
sqlite3 -separator $'\t' ~/.data/oaklib/icd10cm.db \
  "SELECT subject, value FROM statements
   WHERE predicate='rdfs:label' AND subject LIKE 'ICD10CM:Q%';" > /tmp/q_label.tsv
sqlite3 -separator $'\t' ~/.data/oaklib/icd10cm.db \
  "SELECT subject, value FROM statements
   WHERE predicate='oio:hasExactSynonym' AND subject LIKE 'ICD10CM:Q%';" > /tmp/q_syn.tsv
sqlite3 -separator $'\t' ~/.data/oaklib/icd10cm.db \
  "SELECT subject, object FROM edge
   WHERE predicate='rdfs:subClassOf' AND subject LIKE 'ICD10CM:Q%';" > /tmp/q_parent.tsv
sqlite3 -separator $'\t' ~/.data/oaklib/hp.db \
  "SELECT subject, value FROM statements
   WHERE predicate IN ('rdfs:label','oio:hasExactSynonym') AND subject LIKE 'HP:%'
   AND subject NOT IN (SELECT id FROM deprecated_node);" > /tmp/hp_lex.tsv
```

The databases come from `runoak -i sqlite:obo:icd10cm` / `sqlite:obo:hp`.
